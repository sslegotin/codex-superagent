---
name: setup
description: Install, verify or upgrade Codex Superagent in a target Git repository while preserving local project instructions and configuration.
---

Use the user's local distribution checkout. Its installer is `scripts/setup.cjs`. The installed skill lives in the target under `.agents/skills/setup/`. If the source path is unknown, ask where the distribution is checked out.

1. Resolve the target repository root and run `node /path/to/distribution/scripts/setup.cjs discover /path/to/target`. Read its project instructions and existing `.superagent/project.json` if present. Check the actual package manager, check targets, application start command, and any port or database settings. Discovery output provides candidates for the user to confirm.
2. For a fresh install, ask for missing project check commands, the maximum concurrent workers, instructions for running the project, and how each worker gets independent ports and data. A project with no server or persistent data can record that fact. Write the approved settings to a temporary JSON file outside the target. Use the schema in the distribution's `docs/setup.md`. Pass each check as an array containing the executable and each argument separately. Preserve existing project settings on upgrades.
3. Run `node /path/to/distribution/scripts/setup.cjs install /path/to/target --config /path/to/settings.json`. Omit the config flag when project settings already exist. If the installer exits 2, show the differences to the user and ask for a decision for each reported file. Repeat the install command with the printed `--review DIGEST` and one `--keep PATH` or `--replace PATH` per conflict, using the exact target-relative path it printed. A missing required file can be manually restored or replaced.
4. Run `node /path/to/distribution/scripts/setup.cjs verify /path/to/target`, then execute `node .superagent/scripts/superagent.cjs help` from the target root to confirm the runtime starts. Summarize the installed paths, selected project settings, any preserved local variants and any backups. Use the target repository's own Git identity, signing and delivery conventions to record the installation if requested. A ready batch runs only after the user explicitly requests it.
